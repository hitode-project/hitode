# a64 engine

ID prefix: A64
ID prefix: A64F

This spec covers `adv-cpu-a64`, the x86 translator for AArch64 hosts. The shared execution contract is in [execution.md](execution.md), and [README.md](README.md) explains the format. The module docs of `adv-cpu-a64` explain the design.

## Instruction set and scope
### A64-ISA-1 Single-owner execution

**Rule**: All guest threads MUST take turns on one host execution thread. Translated code MUST NOT add TSO barriers and MAY execute locked 32-bit CMPXCHG and CMPXCHG8B natively as one guest instruction. Unsupported locked forms MUST run in the interpreter.
**Applies to**: AArch64
**Verification**: Review — the structure of the execution thread enforces it.

### A64-ISA-2 Capabilities left out

**Rule**: a64 MUST NOT provide a persistent machine code cache, AOT, background compile threads, compile budgets, an interpreter warm-up tier or process snapshot restore.
**Applies to**: AArch64
**Verification**: Review — this limits the scope.

### A64-ISA-3 Interpreter-only mode

**Rule**: `Cpu::new(park, false)` MUST NOT create a code cache or claim host faults. When the host cannot create executable memory, a64 MUST run everything in the interpreter.
**Applies to**: AArch64
**Verification**: Test

### A64-ISA-4 Host instruction set

**Rule**: Emitted code MUST use only ARMv8.0 instructions, and MUST NOT use SVE, SME, MTE, PAC or BTI. FEAT_FlagM MUST be detected at startup, and equivalent sequences MUST replace `rmif` and `cfinv` without it. Windows on ARM hosts are not supported.
**Applies to**: AArch64
**Verification**: Test

> Note: Linux and Android detect FlagM through HWCAP, and macOS through sysctl. FlagM2, AFP and LSE are not used.

### A64-ISA-5 Compare and exchange

**Rule**: CMPXCHG8B MUST preserve flags except ZF, while 32-bit CMPXCHG MUST set arithmetic flags from EAX minus the old destination. Memory destinations MUST be writable even on mismatch and faults MUST preserve registers, flags and destination bytes. Native execution MUST remain indivisible to guest scheduling.
**Applies to**: AArch64
**Verification**: Test

32-bit CMPXCHG replaces the destination on equality and EAX otherwise. Unaligned accesses and checked CMPXCHG8B use the interpreter. Checked 32-bit CMPXCHG uses A64-MEM-7 with complete-instruction fallback.

## Registers
### A64-REG-1 Register assignment

**Rule**: Guest state MUST stay in the AAPCS64 callee-saved registers as the table shows. x18 MUST NOT be used.
**Applies to**: AArch64
**Verification**: Test

| Host | Contents |
|---|---|
| x19 x20 x21 x22 | EAX ECX EDX EBX, read only through the w views |
| x23 x24 | Biased ESP and biased EBP (A64-REG-6) |
| x25 x26 | ESI EDI |
| x27 | Guest window base, aligned to 4 GiB |
| x28 | Shadow return stack pointer |
| x29 | `Runtime` pointer |
| x30 | LR, only for guest call and ret and for helper calls |
| x9 | Safepoint countdown |
| x10 x11 | Canonical lazy sources of PF and AF |
| x12 | DF, 0 or 1 |
| x13 x14 x15 | Flag scratch without FlagM; x15 also holds the lazy carry |
| x16 x17 | Address and exit scratch; w16 holds the guest EIP on dynamic transfers |
| x6 x7 x8 | x6 holds values; x7 and x8 are PF and AF recipe temporaries |
| x0–x5 | Helper arguments; checked accesses borrow x3–x5 |
| NZCV | CF, ZF, SF, OF |
| d8–d15 | MMX cache |
| v16–v23 | XMM0–XMM7 cache |
| v24–v31 | x87 stack values in a run (A64F-FP-7) |
| v0–v6 | SIMD scratch |

### A64-REG-2 Entry and full exit

**Rule**: `enter(runtime, target)` MUST save the host callee-saved registers before it loads guest state. A full exit MUST enter the `exit` stub with the `Exit` in w0 and the guest EIP in w1. The stub MUST write the state back to `CpuState`.
**Applies to**: AArch64
**Verification**: Test

### A64-REG-3 EFLAGS synchronized on demand

**Rule**: The exit stub MUST save only the raw NZCV and x10–x12, and EFLAGS MUST be derived when something reads it. The stub MAY change only CF, PF, AF, ZF, SF, DF and OF in `eflags`.
**Applies to**: AArch64
**Verification**: Test

### A64-REG-4 Light helpers

**Rule**: `dispatch`, `lookup_slow` and `access` MUST NOT access guest registers, and all light helpers MUST save live caller-saved registers. Cache-clearing helpers MUST return 0 for full exit, and `interpret` and `call` MUST synchronize all guest state.
**Applies to**: AArch64
**Verification**: Test

### A64-REG-5 SIMD cache

**Rule**: Caches MUST load on read, and XMM writes MUST update `CpuState` immediately except under A64-TR-5. Caches MUST drop at region heads, merges and helpers, except steady backedges under A64-TR-5. MMX MAY stay dirty under A64F-FP-4, and other x87 state MUST stay in `CpuState` outside runs under A64F-FP-7.
**Applies to**: AArch64
**Verification**: Test

### A64-REG-6 Biased ESP and EBP

**Rule**: x23 and x24 MUST hold x27 plus guest ESP and EBP, so their low 32 bits are the guest values. An operation that writes ESP or EBP MUST compute in 32 bits first, then add the bias again. Offsets MAY fold only into unchecked accesses without an index, with displacements 4-byte aligned in [0, 16384) or within (-256, 256).
**Applies to**: AArch64
**Verification**: Test

> Note: a stack access across 0 or 4 GiB first hits a guard area beside the window, and the interpreter completes it with 32-bit wraparound.

## Flags
### A64-FLAG-1 Carry sense

**Rule**: Materialized SF, ZF and OF MUST occupy N, Z and V of NZCV. C MUST equal CF in add sense and NOT CF in subtract sense, and the translator MUST track the sense statically. Unit and stub boundaries MUST use subtract sense.
**Applies to**: AArch64
**Verification**: Test

### A64-FLAG-2 Bit-exact with the interpreter

**Rule**: Flags from 8-bit and 16-bit operations, logical operations, shifts, multiplication, bit scans and CL shifts MUST match the interpreter bit for bit. This includes which undefined flags are preserved.
**Applies to**: AArch64
**Verification**: Test

### A64-FLAG-3 Precision at fault sites and exits

**Rule**: Fault handlers and unit exits MUST observe exact x86 flags after recovery or canonicalization. Flag liveness MAY omit flags that no guest instruction reads before they are rewritten. Each fault site MUST record carry sense and recipes for every flag it does not hold exactly.
**Applies to**: AArch64
**Verification**: Test

### A64-FLAG-4 Commit after the last fault site

**Rule**: All visible writes of an x86 instruction MUST happen after its last host access that can fault. This includes guest registers, biased stack registers and NZCV.
**Applies to**: AArch64
**Verification**: Test

### A64-FLAG-5 PF and AF

**Rule**: In canonical form, x10 holds the result whose low byte gives PF, and bit 4 of x11 gives AF. Within a unit, flags MAY stay as recipes, but they MUST be materialized before their operands are overwritten. AF MUST be 0 after AND, OR, XOR and TEST.
**Applies to**: AArch64
**Verification**: Test

### A64-FLAG-6 Floating-point compares

**Rule**: The `fcom` and `fucom` families MUST write only C0–C3 of the status word, and MUST NOT change EFLAGS. `fcomi` MUST run in the interpreter. `comiss`, `comisd`, `ucomiss` and `ucomisd` MAY run natively under A64F-FP-5, but NaNs MUST go to the interpreter before changing EFLAGS.
**Applies to**: AArch64
**Verification**: Test

## Floating point
### A64F-FP-1 x87 write-through

**Rule**: Outside runs under A64F-FP-7, the x87 stack, TOP, tags, status word and control word MUST live only in `CpuState`. A natively executed x87 instruction MUST write back only after every check passes.
**Applies to**: AArch64
**Verification**: Test

### A64F-FP-2 Native x87 forms and fallback

**Rule**: Only forms that `fast::classify` accepts and exact signed 64-bit FILD loads MAY run natively. Pending exceptions and MMX state MUST call the interpreter helper in place. Except for FXAM classification, empty or full slots, nonzero denormals and unsupported range/precision MUST call the interpreter helper in place.
**Applies to**: AArch64
**Verification**: Test

FILD m64 normalizes the full integer significand directly into raw80 without binary64 rounding, preserving flags, stack metadata and exception order.

### A64F-FP-3 x87 arithmetic

**Rule**: Native arithmetic MAY accept zeros and normals with normal results, under any rounding control and precision 24, 53 or 64. Results MUST round once from the exact value without narrowing the exponent range, and inexact ones MUST require PE masked. PE and C1 MUST follow that rounding, and compares MUST order equal doubles that lost bits by their exact significands.
**Applies to**: AArch64
**Verification**: Test

### A64F-FP-4 MMX

**Rule**: Except under A64-TR-5, MMX writes MUST publish at exits, control edges, helpers, checked accesses, x87 instructions and cache drops. Boundaries and faults MUST publish dirty MMX and x87 aliases (exponent 0xffff), using site masks and signal contexts. The first MMX instruction of a unit MUST check pending x87 exceptions, then clear TOP and tags.
**Applies to**: AArch64
**Verification**: Test

### A64F-FP-5 SSE

**Rule**: Native SSE floating point MAY run only under default MXCSR, MUST NOT write FPCR, and MAY access FPSR only in its slow path. The fast path MUST have PE set or an exact operation, no denormal operand, and values excluding other exceptions, or take the slow path. Exceptions other than denormal operands and inexact, and unaligned `movaps`-class accesses, MUST leave for the interpreter before committing guest state.
**Applies to**: AArch64
**Verification**: Test

### A64F-FP-6 SSE compares

**Rule**: A compare MUST select its predicate from the low three bits of the immediate, with QNaN exception behavior following the predicate. SNaN operands MUST go to the interpreter. A scalar compare MUST read only the low lane and keep the upper bits of the destination.
**Applies to**: AArch64
**Verification**: Test

### A64F-FP-7 x87 runs

**Rule**: A run MAY span x87 instructions, integer instructions without x87 state or checked accesses, and forward edges to merges reached only from the run. It MAY keep stack values in v24–v31 as exact binary64 pairs, renaming copies, with arithmetic specialized to the translation-time control word behind a guard. It MUST check relied-on tags at entry and fetched values, and MUST publish at exits, helpers and faults as before the faulting instruction.
**Applies to**: AArch64
**Verification**: Test

## Memory
### A64-MEM-1 Window

**Rule**: Each guest process MUST reserve `[x27 − 128 KiB, x27 + 4 GiB + 128 KiB)`, with the 128 KiB on each side inaccessible, except that compact windows follow IOS-MEM-1. Window accesses MUST take the form `[x27, wA, uxtw]`; checked alias accesses MUST also compute guest addresses in 32 bits.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-2 Two views

**Rule**: Guest pages MUST share one memfd between the protected window and the always read-write `Memory::ptr` alias. Generated alias accesses MUST stay within one guest page with raw READ or WRITE and no SHARED, rejecting EXEC for stores. Rust and interpreters MUST use the alias, and mapping, unmapping, protection, code watching, private copies and residency MUST update the window.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-3 Pages left out of the window

**Rule**: SHARED, AUDIO and file overlay pages MUST NOT be committed in the window view, and MUST be handled as soft pages. When `base` is not host-page aligned, placement MUST round down and treat the extra pages as mixed pages.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-4 Page granularity

**Rule**: The 4 KiB permission table MUST be the only authority, and guest-visible mappings and protections MUST NOT depend on the host page size. A host page MUST get the intersection of the R/W permissions of its 4 KiB subpages. Translation MUST check x86 execute permission in the 4 KiB table.
**Applies to**: AArch64
**Verification**: Test

> Note: the host page size comes from `sysconf(_SC_PAGESIZE)` and is 4 KiB or 16 KiB, with one code path for both. Tests can force 16 KiB with `Memory::window_at_host_size`.

### A64-MEM-5 Re-execute after a fault

**Rule**: After a host fault, the owner MUST take the EIP from the side table and re-execute the instruction in the interpreter. The fault address MUST be the first inaccessible byte. A write to a code page MUST first invalidate the affected units.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-6 Adaptive checking per instruction

**Rule**: After an instruction faults `CHECK_AFTER` times at unchecked sites, it MUST be marked checked and its unit MUST be discarded. Faults at checked sites MUST NOT count.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-7 Checked accesses

**Rule**: Checked scalar accesses MUST reject page crossings and test the window class without changing NZCV. Reads MUST require READ without SHARED, while stores MUST require WRITE without EXEC or SHARED. Blocked window accesses MAY use the alias under A64-MEM-2, otherwise they MUST call `access` to complete or refuse them through `Memory`.
Checked SIMD moves MUST use the same permission checks for 4-, 8- and 16-byte accesses; soft or crossing accesses MUST re-execute the complete instruction in the interpreter.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-8 Page class table

**Rule**: The window class table MUST snapshot `Memory::native_permissions`, including host page protection when host pages exceed 4 KiB. Alias accesses MUST use a pinned snapshot of the raw guest permissions. When generated code reads permission tables, the owner MUST refresh both snapshots before native entry, using pointer and version checks for the window table.
**Applies to**: AArch64
**Verification**: Test

> Note: helpers leave translated code after permission revocations. Watched writable pages MUST carry a store barrier even without guest EXEC permission. Channel batches MUST refresh snapshots after linked code discovery changes window protection.

### A64-MEM-9 Signal handler

**Rule**: a64 MUST join the shared SIGSEGV and SIGBUS handler chain through `fault_recovery::install_translated`. a64 MAY claim only faults whose pc is in the code cache and has a side-table entry. Other faults MUST return to the previous handler chain.
**Applies to**: AArch64
**Verification**: Test

> Caution: the handler does not allocate, take locks or schedule.

### A64-MEM-10 Side table

**Rule**: Each host pc that can fault MUST have a side-table entry. Entries MUST record guest EIP, instructions completed, carry sense, lazy carry, PF/AF recipes and SIMD dirty masks. Masks MUST identify MMX registers in bits 0–7 and XMM registers in bits 8–15.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-11 Pages shared with device threads

**Rule**: SHARED and AUDIO pages other than LINEAR ones MUST be inaccessible in the window view, completing accesses through `access`, fault recovery or `Memory` atomics. On unix, the window MUST show shared storage itself on each host page it wholly covers with one protection it takes, without EXEC. A protection breaking that, and an unmap, MUST end this LINEAR view first.
**Applies to**: AArch64
**Verification**: Test

### A64-MEM-13 Shared file views

**Rule**: A shared file view MUST read the pages every other mapping of the file sees, from any 4 KiB-aligned offset. A read-only view MUST refuse guest and host writes. Its pages follow A64-MEM-11.
**Verification**: Test

## Control flow and code cache
### A64-CTL-1 Code cache

**Rule**: The host MUST prepare one fixed code pool before translated execution, leasing each process a contiguous cache of at most 128 MiB. Full caches MUST reset all shadow stacks and indirect tables, reusing the same lease without new executable mappings.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-2 W^X

**Rule**: Executable mappings MUST be owned by the code-view backend. macOS MUST toggle `pthread_jit_write_protect_np` on its `MAP_JIT` range for writes and patches. Linux and Android MUST map one backing twice, writable and executable.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-3 Instruction cache synchronization

**Rule**: Writes MUST only record dirty ranges, which are synchronized before entering translated code and before helpers return. Only the execution thread MAY patch code.
**Applies to**: AArch64
**Verification**: Review — cache coherency errors do not reproduce reliably.

### A64-CTL-4 Call and return

**Rule**: A trace MAY inline static direct calls up to 8 levels deep, and an inlined ret MUST compare with the static return address. A call that is not inlined MUST use `bl` and push `{host continuation, guest return EIP}`. A ret MUST compare the return EIP and execute `ret` only on a match.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-5 Shadow stack mismatch

**Rule**: `ret_miss` MAY check only the 1 to 3 entries below the top, and pops to the entry that matches. Without a match, it MUST NOT change the shadow stack and MUST take the indirect lookup. Each guest thread or fiber MUST have its own shadow stack.
**Applies to**: AArch64
**Verification**: Review — no fixtures cover longjmp, SEH unwinding or fiber switches.

### A64-CTL-6 Indirect jumps

**Rule**: Sites MUST probe the process-wide table inline, except bounded (≤1024 entries) read-only image switches MAY use site tables whose unresolved entries use that probe. Each site MUST retain its own `br`, discards MUST clear the process-wide table, and target discards MUST restore incoming slots to their stub. Cold misses MUST record source EIP and transfer kind, with no hot-path diagnostic instructions.
**Applies to**: AArch64
**Verification**: Test — differential fixtures and emitted site shape.

### A64-CTL-7 Budget

**Rule**: x9 MUST count down guest instructions, and the countdown of one `run` MUST NOT exceed 2^16. Region heads MUST charge the instructions of the segment with `sub` and `tbnz`, not `subs`. Side exits MUST refund the part not executed.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-8 Deadlines

**Rule**: The owner MUST check host interrupts, stops and wall-clock deadlines between calls to `run`. When a host call returns past the deadline, the unit MUST leave before the next instruction starts.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-9 Links and stops

**Rule**: Resolved links MUST use direct `b`, except A64-CTL-6 slots, and restore their original contents when the target is discarded. Known stops MUST end units, remain unlinked and clear the cache when added. Recognized thunks MAY call the host within a unit under A64-CTL-12.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-10 Self-modifying code

**Rule**: Translation MUST call `watch_code` on all trace bytes and specialized switch-table bytes. Writing watched bytes or making table pages writable MUST discard dependent units before the next dispatch. Other data writes on watched pages MUST NOT invalidate units.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-11 Compatibility with patches

**Rule**: Translation MUST NOT bake in values that patches can rewrite, such as import pointers and API entries. Direct API trampolines MUST take the indirect path.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-12 Direct host calls

**Rule**: A recognized thunk MUST call its ordinary handler through the `call` stub, with guest state synchronized as for `interpret`. The call MUST continue in the unit only when it returns to the next instruction and no exit check is due.
**Applies to**: AArch64
**Verification**: Test

| Aspect | Requirement |
|---|---|
| Recognition | An exact `push imm32; int 0x2e` pair MUST lie on registered thunk pages, carry a registered transport word, and not be the guest return entry. |
| Published copies | Every loader, including Wine image mapping, MUST register synthetic DLL code pages containing copied thunks, alongside the private thunk region. |
| Patches | All recognized bytes MUST be watched under A64-CTL-10. Import and entry transfers MUST retain the indirect path under A64-CTL-11. |
| Dispatch | The thunk index MUST be fixed at translation. Tracing and host-call limits MUST apply as for traps. |
| Exit checks | Each return MUST check host interrupts, explicit stops, wall deadlines and code or mapping changes, leaving before the next instruction when required. |
| Without a host | The stub MUST refund the INT and leave for the interpreter. |

## Translation
### A64-TR-1 Decoding and encoding
**Rule**: A table-driven quick decoder handles common opcodes, iced-x86 handles the rest, and both MUST agree. The A64 encoder is written in this project, and an external assembler MUST NOT be added.
**Applies to**: AArch64
**Verification**: Test

### A64-TR-2 Run on the first visit, translate on the second
**Rule**: An entry MUST NOT be translated on its first dispatch. `translate::first` MUST run it once, with the same results as the interpreter. Translation MUST start only when control returns to the same entry.
**Applies to**: AArch64
**Verification**: Test

### A64-TR-3 Traces
**Rule**: A trace MUST be a single tier of at most 96 guest instructions with inlining up to depth 8. A trace MUST NOT build a graph or allocate registers.
**Applies to**: AArch64
**Verification**: Review — this constrains the shape of the translator.

### A64-TR-4 Instructions without native forms
**Rule**: An instruction that the interpreter can run and that does not transfer control MUST become a call to the `interpret` stub, without leaving the unit. Control transfers, fetch failures and invalid encodings MUST emit an exit that interprets one instruction. A unit whose first instruction has no native form MUST NOT enter translated code.
**Applies to**: AArch64
**Verification**: Test

### A64-TR-5 Integer pixel loops
**Rule**: Integer SIMD loops MAY retain MMX/XMM in a NEON steady body after one ordinary iteration establishes the cache. Recognition MUST obey the structural limits below. Exits and faults MUST publish exact state, preserving instruction budgets, memory order and width, stops and code watching.
**Applies to**: AArch64
**Verification**: Test

Recognition uses decoded semantics and resolved edges, without addresses, library names or byte signatures. Each loop has one entry and backedge, without internal merges, calls, helpers, checked accesses, x87 or floating arithmetic; conditional side exits are allowed. The original 96-instruction trace and fixed register mapping remain. Fault recovery restores the exact completed prefix, including MMX aliases, from signal SIMD registers before interpreting the interrupted instruction.

### A64-TR-6 Planar channel batches
**Rule**: Decoded scalar loops interleaving two to four byte channels MAY replace 64 iterations with NEON loads and structure stores. Recognition and runtime guards MUST establish the proofs below. Failed guards MUST execute the original loop without changing guest state.
**Applies to**: AArch64
**Verification**: Test — native/interpreter state and pixels, budget cuts, overlap, bound faults, page boundaries, code barriers and stops on both host page sizes.

Recognition proves stable input/output pointers, temporaries and loop bounds without internal observers, merges, helpers or checked accesses. Guards prove sufficient instruction budget, continuing loop tests, directly accessible single-page ranges, code-watch barriers, and disjoint output/input and output/bound ranges. Proofs include one following scalar iteration that restores every temporary and flag before any observable exit. Stops, code invalidation, fault prefixes and the 96-instruction trace limit remain exact.

### A64-TR-7 Front end and back ends
**Rule**: The front end MUST build a `Unit` from guest memory: the trace, its analysis, its switch tables and the guest bytes it depends on. A back end MUST lower a `Unit` through `Backend` without decoding guest memory again.
**Applies to**: AArch64
**Verification**: Review — this constrains the shape of the translator.

### A64-TR-8 Admitted native byte regions

**Rule**: Admitted byte bridges MUST preserve guest state, memory effects, instruction budgets, stops and invalidation. Preparation MUST specialize parameter mappings and kernel calls. Guards and a non-faulting scalar tail MUST obey the bounds below.
**Applies to**: AArch64
**Verification**: Test

- Hot translation preparation requests independently verified recurrences from the machine's admission service.
- Guards establish nonwrapping ordinary spans, alias conditions, code-watch barriers and sufficient instruction fuel before effects.
- Read spans are independent of the fixed source/output/count/scalar host ABI; every declared span includes the following scalar iteration.
- Fixed private frames check permissions, data separation and invariant slot values before any bulk effect.
- Batches contain 128..=1024 bytes and stay within each buffer's directly accessible page.
- One following scalar iteration restores all temporary registers and flags before an observable exit.
- Its instructions have native forms; interpretation helpers are excluded from the checked tail.
- Code changes and unmapping revoke the ordinary translation containing the bridge.
- Execution neither identifies codecs nor interprets state-view expressions on entry.

## Verification
### A64-VER-1 Differential coverage
**Rule**: Differential tests MUST compare registers, EIP, EFLAGS, memory and outcomes at the stop and at several budget cut points. The configurations MUST cover FlagM on and off, first visits on and off, all accesses checked and all accesses through `access`.
**Applies to**: AArch64
**Verification**: Test

### A64-VER-2 Host page sizes
**Rule**: A change to the a64 memory path MUST be verified with both 4 KiB and 16 KiB host pages.
**Applies to**: AArch64
**Verification**: Test

### A64-CTL-13 Code pool capacity

**Rule**: A short pool MUST halve iOS leases down to 16 MiB before warning and running Tier 0; other hosts MUST map overflow caches separately. Process exit MUST return its lease, coalescing adjacent free ranges, and pool configuration MUST be fixed after preparation.
**Applies to**: AArch64
**Verification**: Test

The default pool is 512 MiB, configured by `ADV_A64_CODE_POOL_MIB` before the first cache is created. Hosts may call `prepare_code_pool` explicitly before creating machines.

### A64-CTL-14 Redirected functions

**Rule**: A trace reaching a redirected function entry MUST jump to the owner's target while the guest bytes there equal the owner's copy. It MUST watch those bytes under A64-CTL-10. Trace, host-call limits and the interpreter MUST run the function itself.
**Applies to**: AArch64
**Verification**: Test

The owner's target is an ordinary thunk, so its call follows A64-CTL-12.

### A64-MEM-12 Dual-view backend

**Rule**: Platform backends MUST provide coherent aliases of the same backing for code, device storage and guest windows. Owners MUST stop readers before unmapping dependent views, then writable aliases. On iOS, data aliases MUST map a Mach named memory entry, and no view MAY allow both write and execute.
**Verification**: Test

Code publication follows A64-CTL-3: synchronize writable data and executable instruction views before executing writes or patches. Data aliases require no instruction-cache flush. Linux/Android use memfd, macOS data uses POSIX shared memory, and Windows device storage keeps section mappings.

Withdrawn: A64-FP-1, A64-FP-2, A64-FP-3, A64-FP-4, A64-FP-5, A64-FP-6
